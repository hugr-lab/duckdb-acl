# Spec 090: re-pin duckdb to the result-format world

- **Status**: implemented
- **Date**: 2026-09-30
- **Found by**: the distribution build of PR #167. Distribution compiles the head of
  `v2.0-cyanoptera`, and it stopped compiling our sources:
  `'class duckdb::QueryResult' has no member named 'GetValue'`.

## Summary

The duckdb submodule moves from d4e7256 (2026-09-22) to 96063b9 (the branch head of 2026-09-30, 616
commits). quack moves with it to the submodule's own pin, 974927a. The sources follow three upstream
API changes, and a helper keeps row reads linear.

## Problem

Upstream changed three things our code relies on:

- **ResultFormat** (duckdb 7b7ee6f): a result's format is fixed at submission. `QueryResult` lost
  `GetValue(column, row)`, and `QueryResultStream` became a template over the format. The replacement
  duckdb uses, `result->Collection().GetValue(c, r)`, calls `ColumnDataCollection::GetRows()`, which
  builds a `ColumnDataRowCollection` of **every** row on each call. The old `QueryResult::GetValue`
  kept that collection. A mechanical rename would make every loop over a result quadratic: policy
  loads, listings, the catalog check, the Flight catalog RPCs.
- **Function signatures**: a table function's parameters are a `FunctionSignature`
  (`AddParameter`, typed kwargs), not `arguments` / `named_parameters`. A bound table function's
  name is `GetName()`.
- **quack**: duckdb's pin moved to 974927a (CONNECT out of the transaction mechanism, the
  self-CONNECT guard, and duckdb's own patches upstreamed). duckdb now carries a function-signature
  patch for it.

## Design

- **`ResultRows`** (`src/include/acl_result_rows.hpp`) is the rows of a materialized result, built
  once, with `GetValue(column, row)` and `Count()`:
  - Every loop over a result builds one right after the result is assigned and reads cells from it.
  - Single-row reads (`GetValue(c, 0)` of a one-row answer) use `Collection().GetValue` directly.
  - `CatalogBackend::RowPolicy` takes the caller's `ResultRows`, because it is called once per row.
  - The Flight catalog's `BatchFrom` / `SchemasFor` build theirs once per result.
- `FlightDoorState::ResultStream` holds a `QueryResultStream<>` (the chunk format).
- The quack embed is regenerated by `sync.py` from 974927a. duckdb's 0002 patch (function
  signatures) applies to the embed's copies. 0001 touches a quack test only and is skipped. Our own
  hunks (the driver's profile/audit calls, the fetch window, the seats) all applied unchanged.
- Tests: `test_acl_foreign_parser`'s toy table function declares its parameter through the signature;
  `test_acl_secrets` names the bound function with `GetName()`.

## Enforcement & security

No behaviour changes: the same statements are composed and the same values read. The quack embed's
patched hunks are unchanged, so the door's gates (authorization callback, seats, stream budget, fetch
window) are the ones they were.
